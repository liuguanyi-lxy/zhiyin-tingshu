# 前端结构导读 —— 从编译产物理解 uni-app（Vue）小程序

> 本项目 `mp-weixin/` 目录是 uni-app 编译后的微信小程序产物（`.vue` 源码已遗失）。
> 但编译器保留了完整的逻辑骨架：Vue Composition API（`setup`/`ref`）、Pinia 状态管理、
> 业务分层（api / stores / hooks）全部可读。本文档带你按"请求链路 → 状态管理 → 页面结构 → 业务流程"
> 的顺序读懂它，并把每个概念映射回 Vue/uni-app 源码写法。

## 1. 编译产物 ↔ Vue 源码对照表

读代码前先建立映射，看到编译产物不要慌，它只是把 `.vue` 文件拆开了：

| uni-app 源码 | 编译产物 | 说明 |
|---|---|---|
| `pages/detail/detail.vue` 的 `<template>` | `pages/detail/detail.wxml` | 模板编译成小程序 wxml，绑定的 `{{a}}`、`{{b}}` 是变量被重命名后的代号 |
| 同一个 `.vue` 的 `<script setup>` | `pages/detail/detail.js` 中的 `_sfc_main` | **逻辑原样保留**，`setup`、`ref()`、`onLoad()` 一眼可认 |
| 同一个 `.vue` 的 `<style>` | `pages/detail/detail.wxss` | 样式基本原样 |
| `src/pages.json` | `app.json` | 页面注册表、窗口配置 |
| `src/manifest.json` | `project.config.json` | appid、编译设置 |
| `src/main.js` + 框架运行时 | `common/vendor.js`（344KB） | Vue 运行时 + Pinia + uni-app 运行时全在这，**不用读** |
| 全局组件注册 | `app.js` 里的 `if (!Math) { "./pages/..." }` 块 | 编译器注入的组件懒加载清单 |

**读法结论：只读 `pages/**/*.js`、`api/`、`stores/`、`utils/`、`hooks/`，跳过 vendor.js 和 wxml。**

## 2. 目录结构与分层

```
mp-weixin/
├── app.js / app.json / app.wxss   # 小程序入口：页面注册、全局样式

├── utils/

│   └── utils.js                   # setRedirectUrl 等工具函数
├── api/                           # ★ 接口层：按后端微服务分模块（user/order/albums/...）
│   ├── user/user.js               #   登录、用户信息
│   ├── order/order.js             #   下单、支付状态轮询
│   ├── albums/ albums.js          #   专辑/声音
│   └── search/ category/ ...      #   其余服务一一对应
├── stores/                        # ★ Pinia 状态仓库（user/order/player...）
├── hooks/                         # 组合式函数（useUpdateUserInfo 等）
├── pages/                         # 28 个页面，一个目录一个页面
├── components/                    # 自定义组件
```

分层与后端惊人地对称：`api/` ≈ 你的 Feign 客户端，`stores/` ≈ 服务的本地状态，`request.js` ≈ 网关+统一响应处理的前端版。

## 3. 请求链路（最值得读懂的一条线）

**第 1 层：`config/confjg.js`** —— 后端地址，指向网关 8500：
```js
const BASE_URL = "http://localhost:8500";
```

**第 2 层：`utils/request.js` 的 `Service` 类** —— 相当于前端版的"网关过滤器 + 全局异常处理"：
```js
api(opts) {
  const token = stores_user.useUserStore().token;   // 1. 从 Pinia 取 token
  const header = { token, ... };                    // 2. 放进请求头（后端 AuthGlobalFilter 就收这个）
  return new Promise((resolve, reject) => {
    if (opts.loading) index.showLoading(...);       // 3. 统一 loading
    index.request({
      url: BASEURL + opts.url, data, method, header,
      success: (res) => {
        if (res.data.code == 200) resolve(res.data);          // 4a. 成功
        else if (res.data.code == 208) { ...redirectTo login } // 4b. 登录过期 → 弹窗 → 跳登录页
        else { showToast(res.data.message); reject(...); }     // 4c. 业务异常 → toast
      }
    });
  });
}
get/post/put/delete(options) { ... }   // RESTful 便捷方法
```
**与后端的呼应**：`code==208` 的处理分支正好对应你网关 `AuthGlobalFilter` 返回的 `LOGIN_AUTH(208)`，
前后端通过这一个约定值闭环了"token 失效 → 重新登录 → 登录后跳回原页面"（`setRedirectUrl`）的完整体验。

**第 3 层：`api/*` 模块** —— 每个后端微服务一个类，继承 Service：
```js
class User extends Service {
  getLogin(code)        { return this.get({ url: `/api/user/wxLogin/wxLogin/${code}` }); }
  getUserInfo()         { return this.get({ url: `/api/user/wxLogin/getUserInfo` }); }
}
```
页面里永远只调 `user.getLogin(code)`，不直接碰 request —— 和后端 Controller 只调 Service 一个道理。

## 4. 状态管理：Pinia（Vue 官方推荐的状态库）

`stores/user.js` 是最典型的一个，编译后 `defineStore` 原样保留：
```js
const useUserStore = defineStore("user", {
  state: () => ({                              // 响应式状态
    user: JSON.parse(getStorageSync(USER_KEY) || "{}"),  // 从本地缓存恢复（登录持久化）
    token: getStorageSync(TOKEN_KEY),
    amount: 0
  }),
  actions: {                                   // 修改状态的方法（可含异步）
    async loginWithWechat() {
      index.login({ success: async (res) => {
        await this.getToken(res.code);         // wx.login 拿 code → 调后端换 token
        await this.getUserInfo();              // 拉用户信息
        index.redirectTo(redirectUrl || "/pages/index/index");  // 跳回来源页
        await this.getAccountBalance();
      }});
    },
    async getToken(code) { const res = await user.getLogin(code);
      setStorageSync(TOKEN_KEY, res.data.token); this.token = res.data.token; }
  }
});
```
**要点**：`state` 持久化到 Storage（小程序没有 cookie，token 靠 `StorageSync` 存活于下次启动），
`actions` 就是"组件里调用、内部改 state"的业务方法。所有页面共享这一个用户状态，
这正是 Pinia 存在的意义——替代 props 层层传递。

## 5. 页面结构剖析：以 `pages/detail/detail.js`（专辑详情页）为例

编译后依然能看到标准的 Vue Composition API：

```js
const _sfc_main = defineComponent({
  __name: "detail",
  props: { id: {...} },              // 页面参数：/pages/detail/detail?id=123
  setup(__props) {
    const userStore = useUserStore();       // 注入 Pinia
    const albumDetailInfo = ref({});        // 响应式数据（相当于 data）
    const isSubscribe = ref(false);
    const getAlbumDetailInfo = async () => {              // 业务方法
      const res = await albumsService.getAlbumDetail(props.id);
      albumDetailInfo.value = res.data;     // .value 赋值 → 模板自动更新
    };
    onLoad(() => { getAlbumDetailInfo(); });   // 页面生命周期：进页面就拉数据
    onShow(() => { ... });                     // 从其它页返回时刷新
    return { albumDetailInfo, ... };           // 返回给模板使用
  }
});
```

**Vue 概念对照**：
- `ref()` ≈ `data` 里的响应式字段，`.value` 读写，模板自动联动
- `onLoad` / `onShow` ≈ Vue 的 `onMounted`，但语义是小程序页面的"加载/每次可见"
- `props` 接收路由参数，对应页面 URL 的 `?id=`
- `zPagingRef.value.complete(records)` —— `ref()` 也能指向组件实例，调子组件方法（分页组件回填）

wxml 里那些 `{{a}}` `{{b}}` 是编译器把 `albumDetailInfo.xxx` 重命名后的代号，
**不要去读 wxml 对应关系**，理解 js 就理解了页面。

## 6. 核心业务流程串讲（对照你的后端）

### 6.1 登录流程
```
login 页 → store.loginWithWechat()
  → wx.login() 拿临时 code
  → GET /api/user/wxLogin/wxLogin/{code}      ──→ 后端拿 code 换 openid、签发 token 存 Redis
  → token 写入 Storage + Pinia
  → getUserInfo() 拉资料 → 若无头像昵称则 wx.getUserInfo 授权补全
  → redirectTo(redirectUrl || 首页)
```
之后每个请求 `request.js` 自动带 token 头，网关 Redis 校验，失效返回 208 → 弹窗重登。

### 6.2 购买流程（和后端四个服务对齐）
```
detail 页选集/买专辑 → confirmOrder 页（结算页）
  → 后端 trade() 结算 + SignHelper 签名防篡改
  → 提交订单 submitOrder（tradeNo Lua 防重）→ 得到 orderNo
  → createJsapi/{paymentType}/{orderNo}      ──→ 后端微信下单，返回 paySign 等五件套
  → uni.requestPayment(五件套) 拉起微信收银台
  → 用户支付 → 微信服务器回调后端 /notify（修复#5 新增）+ 前端轮询 queryPayStatus 兜底
  → paySuccess 页
stores/order.js 在这个流程里负责跨页传递订单数据。
```

### 6.3 收听流程
player 页 → 专辑/声音接口 + 收听进度上报（`userListenProcess`）→ 断点续播；
`requiredBackgroundModes: ["audio"]`（app.json）保证锁屏继续播。

## 7. UI 框架与组件来源

| 来源 | 是什么 |
|---|---|
| `Grace6/` | 课程配套的付费 UI 框架：`gui-page`（页面骨架）、`gui-popup`、`gui-header-leading` 等 |
| `uni_modules/` | uni-app 插件市场组件：`z-paging`（下拉刷新+无限分页，detail 页在用）、`mp-html`（富文本）、`cl-upload`（上传，修复#4 配套改过） |
| `components/` | 项目自定义组件 |

模板里直接写 `<gui-page>`、`<z-paging>` 就能用，这是 uni-app 的 easycom 自动注册机制——编译产物里表现为 `app.js` 和页面 js 头部的 `resolveComponent` 声明。
