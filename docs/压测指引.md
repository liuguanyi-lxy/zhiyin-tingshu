# JMeter 压测指引 —— 验证简历"10 万级曲库检索"性能声明

> 目标：用真实压测数字支撑简历语句"10 万级曲库数据下检索耗时由数百 ms 降至数十 ms"。
> **实测是多少就写多少**——数字的真实性比数字的大小值钱。
> 前置：中间件在线（MySQL/Redis/RabbitMQ/ES/Nacos，配置见 Nacos），本机 JDK 17，JMeter 5.5+（[下载](https://jmeter.apache.org/download_jmeter.cgi)，解压即用）。

## 压测对象与口径

| 对照 | 接口 | 端口 | 说明 |
|---|---|---|---|
| 基线 | `GET /api/album/albumInfo/likeBenchmark/{keyword}` | 8501（album 服务） | `LIKE '%kw%'`，无法走索引，全表扫描 |
| ES 版 | `POST /api/search/albumInfo`，body `{"keyword":"${keyword}","pageNo":1,"pageSize":10}` | 8502（search 服务） | 倒排索引检索 |

**直连服务端口、不经网关**：隔离对照变量（不测网关转发开销），50 线程压本机服务。

## 第 1 步：凑数据到 10 万级（约 2 分钟）

```bash
mysql -uroot -p < docs/压测/pad_albums_100k.sql
```
以 id≤1500 的真实专辑为模板复制 66 轮（分类/用户沿用真实值，保证上架链路可用），约 10 万行。

## 第 2 步：ES 灌数（约 10~30 分钟，跑一次即可）

```bash
# 先启动 service-album、service-search（IDEA 或 mvn spring-boot:run），然后：
curl http://localhost:8502/api/search/albumInfo/batchUpperAlbum/100500
```
`100500` 按第 1 步的 after_count 调整。每个专辑走真实上架链路（Feign 查专辑/分类/用户 → 写 ES）。

## 第 3 步：预热（重要，防止 ES 冷启动拉高首轮数据）

两个接口各手动点 20 次左右，或先用 JMeter 1 线程 20 循环跑一轮丢弃结果。

## 第 4 步：正式压测

JMeter 打开 `docs/压测/like-baseline.jmx` → 启动 → 等聚合报告稳定（1000 采样）→ 记录：
**Average、Median、90% Line（P90）、Throughput、Error%**。
同法跑 `es-search.jmx`。两个结果文件 `like-results.csv` / `es-results.csv` 落在 JMeter 启动目录。

> 非 GUI 模式（更准，推荐第二次正式跑）：
> `jmeter -n -t docs/压测/like-baseline.jmx -l like-res.csv`
> 结束后 GUI 打开 like-res.csv 看，或直接算均值。

## 第 5 步：写回简历

用实测数字替换，格式模板（按实际值填）：

> 10 万级曲库数据下，JMeter 50 并发压测（1000 采样/组），关键词检索 P90 由约 XXX ms 降至约 XX ms，错误率 0%

建议同时记录：两边数据量一致（10 万行/10 万文档）、同机压测、预热后采样——面试追问时逐条能答。

## 面试追问预案

- **"为什么 LIKE 慢？"** — `%kw%` 前缀通配使 B+ 树索引失效，逐行扫描 10 万行；ES 倒排索引按词项直接定位文档。
- **"为什么 ES 快也不能替代 MySQL？"** — ES 是检索引擎，非事务主存储；本项目 MySQL 仍是主库，ES 是检索视图，MQ 事件驱动同步。
- **"压测的局限？"** — 单机自压（服务与 JMeter 同机，存在资源竞争），数据是复制生成的均匀分布，生产应独立压测机+真实分布。**主动说这个比被指出强。**

## 故障排查

| 现象 | 处理 |
|---|---|
| 全部 502/Connection refused | 服务没起，先起 service-album / service-search |
| LIKE 接口 500 | 看 album 服务日志：多半是数据没灌（表为空不影响，应返回空数组） |
| ES 检索 500 | search 服务日志看 ES 连接；确认第 2 步灌数完成 |
| 响应时间都 <5ms | 数据没凑够 10 万级，回到第 1 步 |
